D:\M_X_M 项目梳理

当前文件夹是一个多项目工作区，主要围绕 Agent、AI 应用、可视化、游戏、测试平台和 2D 转 3D 工具展开。本文档基于根目录、README、package 配置、pubspec、pyproject 与项目结构生成。

更新日期：2026-06-29 顶层项目：10 个 根目录不是 Git 仓库 独立 Git 仓库：3 个 主要语言：TypeScript / Dart / Python

一、总体结论

10顶层项目目录
7+Node / TypeScript 项目
1Flutter 移动端项目
1大型 pnpm monorepo

主线方向：工作区具有明显的 Agent 实验与产品化倾向：从最小 ReAct Agent、Agent 主循环基座，到旅行规划、道德困境交互、轨道调度游戏 AI、跨端 E2E Agent 平台，再到移动端智能助手。

工程风格：多数项目采用 Node 20+、TypeScript ESM、Vite、tsx、ESLint 9、Prettier、node:test，并强调离线可运行、OpenAI 兼容接口、本地代理保护 API Key、纯逻辑层可测试。

部署形态：既有纯静态前端，也有 Vite + 本地 Node server，全栈工具类应用，Flutter 客户端，以及 Next.js + pnpm workspace 的平台型 monorepo。

当前重点：e2e-fusion 是规模最大的工程化平台；agentloop 是可复用的 Agent 基座；tripplan 是状态驱动 Agent 产品样板；agentapp 是移动端落地入口；modelstudio 是 3D 生成工具链方向。

三、单项目梳理

agentapp

安卓优先的 AI 智能助手应用，内置工作、学习、生活、通用四类专业 Agent，并由路由 Agent 自动分发任务。核心特征是纯端侧架构：无后端，API Key 保存在本机安全存储中。

FlutterDartRiverpodSQLiteOpenAI 兼容

移动端 App
  • 主要模块：lib/core 常量/主题/数据库，lib/data LLM 客户端与仓储，lib/domain Agent 与 prompt，lib/presentation UI。

  • 命令：flutter pub get、flutter run、flutter test、flutter build apk --debug。

agentloop

六、共性模式

  • 离线优先：多个项目无 API Key 也能运行，使用 StubLLM、种子数据或预设剧本兜底。
  • OpenAI 兼容：LLM 接入普遍抽象为 base URL、API key、model，便于切换服务商。
  • 本地代理保护密钥：网页项目通常由本地 Node server 读取密钥，浏览器只访问同源 API。
  • 逻辑与 UI 分离：游戏和行程项目把核心规则放在纯逻辑模块，便于单测和复用。
  • Agent 工具调用：agentloop、agentresearch、tripplan、e2e-fusion 都强调工具 schema、状态变更和可观察轨迹。

七、观察点与建议

1. 根目录不是 Git 仓库。如果这些项目需要统一版本管理，应考虑把当前目录初始化为上层 meta repo，或者保持每个项目独立 Git 仓库并建立清晰说明。

2. kids-games 文档存在数量不一致。README 顶部宣称 49 个游戏，但 package 描述和结构说明仍是 8 个。建议以实际 src/games 注册表为准统一 README、package 描述与测试说明。

3. 多个项目已安装 node_modules。工作区整体体积和扫描噪声较大。建议后续统计、搜索、备份和归档默认排除 node_modules、dist、.next、build。

4. 可以抽一个共享工程模板。env 加载、retry、OpenAI 兼容 LLM 客户端、StubLLM、本地代理、node:test 配置在多个项目重复出现，适合沉淀为模板或内部包。

5. 建议建立工作区索引。可增加根目录 README.md，说明每个子项目的定位、运行命令、端口、依赖和维护状态，降低后续切换成本。
