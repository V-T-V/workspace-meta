# 密码强度 · 设计笔记

## 本包定位

本包是 crypto-atlas 里少数**非密码学原语**的包：它不产生密文或摘要，
而是评估口令（password）的强度。把它放进 atlas 是为了和哈希（sha256/md5）、
口令存储形成对照——**"先判断口令够不够强"是"再把它哈希存库"的前置步骤**。

它解决的问题是：在注册改密表单给用户即时反馈"这个口令算弱还是强"，
以及教学演示"什么样的口令算弱"。

## 评分规则（满分 100）

| 维度 | 分值 | 说明 |
|------|------|------|
| 长度 | 最多 40 | 每字符 +4，上限 40 |
| 小写字母 | +15 | 至少 1 个小写字母 |
| 大写字母 | +15 | 至少 1 个大写字母 |
| 数字 | +15 | 至少 1 个数字 |
| 特殊字符 | +15 | 至少 1 个非字母非数字字符 |
| 常见弱口令 | 清零 | 命中黑名单直接判 0 分、级别强制 weak |

级别阈值：

- `Score < 40` → **weak**
- `40 <= Score < 80` → **medium**
- `Score >= 80` → **strong**

## 最小可识别特征

1. **规则评分**：把强度拆成可观察的几条规则（长度 + 字符种类 + 黑名单）
2. **三档输出**：weak / medium / strong，对应 0-100 分数
3. **可解释**：`Reasons` 字段逐条列出加减分依据

## 判定红线

- **不能**当作口令存储：本包不哈希、不加盐，只评估强度。
  存储请用 bcrypt / Argon2 / scrypt。
- **不能**当作唯一安全门槛：强度分数只是启发式估计，不抗针对性攻击
  （字典攻击、个人信息组合攻击等）。
- 黑名单是**教学样本**（20 条典型弱口令），真实系统应使用更大的泄露口令库
  （如 Have I Been Pwned 的 Pwned Passwords）。

## 为什么这样设计评分

- **长度权重最高（最多 40 分）**：长度是口令熵最主要的来源，4 类齐全的短口令
  仍可能被穷举。长度 × 4、上限 40 让"够长"成为拿高分的前提。
- **字符种类每类 15 分**：鼓励四类齐全（大小写 + 数字 + 特殊），但不让任一类
  权重过高——纯靠"加一个特殊字符"无法把弱口令救成 strong。
- **黑名单一票否决**：`123456` 这类即使长度分数够，也几乎瞬间被字典攻破，
  所以命中即清零，级别强制 weak。

## 与其他包的关系

- 与 **sha256/md5**：那些是单向哈希（不可逆摘要）；本包不哈希，只打分。
- 与口令存储（atlas 暂未实现 bcrypt 包）：本包是存储前的"前置校验"，
  真正存储用加盐慢哈希（bcrypt/Argon2/scrypt），二者配合：
  先用本包拒绝弱口令，再用慢哈希存储。

## 本包实现要点

- 纯标准库：`unicode` 做 rune 分类，`strings` 做小写化匹配黑名单
- rune 计数长度（`len([]rune(s))`），对中文等非 ASCII 友好
- 特殊字符 = 非字母非数字（含空格、标点、符号）
- 黑名单小写匹配，避免大小写变体绕过
- `Reasons` 字段让评分可解释（demo/调试/前端反馈都能直接展示）

## 局限与改进方向

- 黑名单规模小（教学样本）；真实系统应接 Pwned Passwords API
- 不识别键盘序列（`qwerty`、`asdfgh`）、重复（`aaaaaa`）、日期等模式
- 不识别个人信息（生日、姓名）组合
- 评分是线性加权；更严谨的做法是用熵估计或 zxcvbn 这类基于字典+组合的算法
