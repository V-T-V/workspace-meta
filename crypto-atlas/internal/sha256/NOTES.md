# SHA-256 · 设计笔记

## 历史

- 由 NSA 设计、NIST 在 **FIPS 180-2（2002）** 标准化，属于 SHA-2 家族（含 SHA-224/256/384/512）
- 是当前工业界部署最广的哈希函数：TLS 证书、区块链（比特币用 SHA-256d）、Git（与 SHA-1 并存）、密码存储等
- 至今无实用级别的碰撞攻击，仍是推荐首选

## 核心算法（高层）

```
输入任意长度 M：
  1. 填充到 512 位（64 字节）的整数倍（追加 1 位 + 填 0 + 64 位长度）
  2. 切成 512 位的块，逐块送入压缩函数
  3. 压缩函数做 64 轮运算（消息调度 + 工作变量更新），状态为 256 位
  4. 最终的 256 位工作变量即摘要
```

本包**不手写压缩函数**，直接用 Go 标准库 `crypto/sha256`——
标准库实现经过审计、有硬件加速（SHA-NI），远比手写可靠。

## 最小可识别特征

1. **无密钥**：任何人都能算同一个摘要，没有"加密密钥"概念
2. **不可逆（单向）**：从摘要无法（在计算上）反推输入
3. **定长输出**：无论输入 0 字节还是 1GB，输出恒为 32 字节（256 位）
4. **雪崩效应**：输入改 1 位，输出每个比特都有约 50% 概率翻转

## 判定红线

- 如果**有密钥**且**可解密还原原文** → 是**加密**（对称/非对称），**不是**哈希
- 如果**有密钥**但**仍不可逆** → 是 **HMAC / 带密钥哈希**（用于消息认证），**不是**纯哈希
- 如果输出可变长度 / 不是 32 字节 → 不是 SHA-256（可能是 MD5=16、SHA-1=20、SHA-512=64）
- 如果"输出短、可碰撞" → 是已被攻破的哈希（MD5/SHA-1），不应再用于安全场景

## 哈希 vs 加密（核心区别）

| 维度 | 加密（对称/非对称） | 哈希（SHA-256） |
|------|---------------------|------------------|
| 密钥 | 有 | **无** |
| 可逆 | 可解密还原原文 | **不可逆**（无法从摘要还原输入） |
| 输出 | 与输入同量级 | **定长**（32 字节） |
| 目的 | 保密 | 完整性 / 指纹 / 不可抵赖 |

## 安全性分析

- **抗碰撞**：找两个不同输入有相同摘要，难度约 2^128（生日攻击下界）
- **抗原像**：给定摘要反推输入，难度 2^256
- **抗第二原像**：给定一个输入找另一个同摘要输入，难度 2^256
- **生日攻击**：碰撞攻击的复杂度是平方根关系——256 位摘要的安全强度相当于 128 位
  （这也是为什么 SHA-256 的"有效安全强度"被记为 128 位）

## 与 MD5 对比

| 维度 | MD5 | SHA-256 |
|------|-----|---------|
| 输出 | 16 字节（128 位） | 32 字节（256 位） |
| 轮数 | 64（4 轮 ×16 步） | 64 |
| 碰撞攻击 | **已被攻破**（王小云 2004，秒级） | 无实用攻击 |
| 现状 | 禁用于安全场景 | 推荐首选 |

## 应用

- **完整性校验**：文件下载、软件包指纹（`sha256sum`）
- **区块链**：比特币区块头工作量证明（SHA-256d）
- **密码存储**：存 `SHA-256(密码 + 盐)` 或更安全的 Argon2/bcrypt
- **数字签名**：先哈希再签名（对 32 字节签名比对整条消息签名快得多）
- **HMAC**：带密钥哈希，用于消息认证（TLS、JWT）

## 本包实现要点

- 直接调用标准库 `crypto/sha256.Sum256`，不手写压缩函数
- 用 `core.HexEncode` 把 32 字节摘要转成 64 字符 hex 小写串
- demo 演示三大特性：定长输出 / 雪崩效应 / 单向
