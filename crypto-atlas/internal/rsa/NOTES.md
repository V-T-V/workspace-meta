# RSA 公钥密码 · 设计笔记

## 历史

- 1977 年由 MIT 的 **Rivest / Shamir / Adleman** 三人提出（算法名取自姓氏首字母）
- 灵感源自 Diffie-Hellman 1976 年"公钥密码"概念的提出
- 是首个可实用的公钥加密 + 数字签名算法，1977 年发表于 *Scientific American*（Martin Gardner 专栏）让 RSA 一夜成名
- 1982 年三人成立 RSA Security 公司；2000 年 RSA 算法专利到期，进入公有领域

## 数学基础

```
选两个大素数 p, q
N = p * q                        模数，公开
φ(N) = (p-1)(q-1)                 欧拉函数（≤N 且与 N 互素的正整数个数）
选 E：1 < E < φ(N)，且 gcd(E, φ(N)) = 1     公钥指数（常取 65537=2^16+1，教学取 17）
算 D：D = E^-1 mod φ(N)           私钥指数（E 对 φ(N) 的模逆元）

公钥 = (N, E)    可公开
私钥 = (N, D)    必须保密
```

加解密 / 签名（都是模幂运算）：

```
加密：c = m^E  mod N      （公钥，任何人都能做）
解密：m = c^D  mod N      （私钥，只有 D 持有者）
签名：s = m^D  mod N      （私钥，"用私钥加密"）
验签：m ?= s^E mod N      （公钥，"用公钥解密"）
```

### 为什么 m = c^D mod N 能还原 m？

由 D ≡ E⁻¹ (mod φ(N)) 知 `E·D ≡ 1 (mod φ(N))`，即 `E·D = 1 + k·φ(N)`。

当 `gcd(m, N) = 1` 时，由**欧拉定理** `m^φ(N) ≡ 1 (mod N)`：

```
(m^E)^D = m^(E·D) = m^(1 + k·φ(N)) = m · (m^φ(N))^k ≡ m · 1^k ≡ m (mod N)
```

（gcd(m,N)≠1 的情形由 CRT 可单独证明，结论相同。）

## 为什么安全？

- 攻击者已知公钥 `(N, E)`，要解密必须求 `D`，而 `D = E⁻¹ mod φ(N)`
- 求 `φ(N)` 等价于**分解 N**：因为 `φ(N) = (p-1)(q-1) = N - (p+q) + 1`，知道 φ(N) 就能解出 p+q，从而分解 N
- **大整数分解**是公认困难问题：目前最好的通用算法（数域筛 NFS）分解 n 位整数约需 `exp(∛(ln n)^(1/3))` 量级运算
- 因此"分解 N 之难" ⟺ "破解 RSA 之难"（虽未被证明等价，但至今无更快的攻击）

实际 RSA 推荐：

| 安全强度 | 模数 N 位数 | 备注 |
|---------|-----------|------|
| 80 bit  | 1024 bit  | 已不安全（2010 年起被分解记录逼近） |
| 112 bit | 2048 bit  | 当前最低可接受 |
| 128 bit | 3072 bit  | 长期推荐 |
| 256 bit | 15360 bit | 抗量子？不，Shor 算法可破 |

> 量子计算机上 **Shor 算法**能在多项式时间内分解大整数，因此 RSA 不具备"后量子"安全。
> 后量子密码（PQC，如 NIST 标准化的 ML-KEM / Dilithium）正在替代它。

## 填充的重要性（本包省略，但必须知道）

直接对"裸"数值 m 做 `m^E mod N` 是**确定性加密**，存在严重缺陷：

- 相同明文 → 相同密文（可被字典攻击）
- 可被选择密文攻击（CCA）利用
- 签名场景可被存在性伪造（hash 后再签可缓解）

实际标准用 **OAEP**（加密）和 **PSS**（签名）做随机化填充，本教学版省略以突出数学。

## 应用

- **HTTPS / TLS**：握手阶段用 RSA（或 ECDHE）协商对称密钥，随后用 AES 加密流量
- **数字签名**：代码签名（ Authenticode ）、邮件（PGP / S/MIME）、PDF 签名
- **SSH**：服务端 host key 长期用 RSA（现逐步迁移到 Ed25519）
- **PGP Web of Trust**：身份信任链建立在 RSA 签名之上

## 与对称密码 / DH 的对比

| 维度 | 对称（AES） | RSA | DH |
|-----|-----------|-----|-----|
| 密钥 | 单密钥共享 | 公/私钥对 | 协商出共享密钥 |
| 能否加密 | ✓（快） | ✓（慢，只加密小块） | ✗（只协商密钥） |
| 能否签名 | ✗ | ✓ | ✗（需结合签名） |
| 速度 | 极快 | 慢（~1000x AES） | 慢 |

实务中几乎总是 **混合**：用 RSA/DH 协商一把对称密钥，再用 AES 加密数据。

## 本包实现要点

- 用 `math/big.Exp(base, exp, mod)` 做模幂（非 nil 第三参即模幂，O(log exp)）
- 用 `big.Int.GCD` 判 `gcd(E, φ(N))==1`
- 用 `big.Int.ModInverse(E, phi)` 求 D
- 用 `ProbablyPrime(20)` 做素性检查（教学级，非密码学确定性）
- 签名 = `m^D mod N`，验签 = `sig^E mod N == m`（与加解密同一对模幂，凸显 RSA 数学对称性）

## 判定红线

"少了下面任意一条就不算 RSA"——评审时按此清单逐项核对：

- **必须基于大整数分解难题**。密钥来自两个大素数 p, q 的乘积 N = p·q，安全性建立在"分解 N 困难"之上。
  - 若算法不基于分解（如基于离散对数），那是 DH/ElGamal，不是 RSA。
  - 若 p, q 不是素数，N 的因子结构错乱，欧拉函数 φ(N) 不再等于 (p-1)(q-1)，整个数学基础崩塌。
- **加密和解密必须可逆（互逆运算）**：
  - 加密 `c = m^E mod N`，解密 `m = c^D mod N`，必须满足 `(m^E)^D ≡ m (mod N)`。
  - 这依赖 `E·D ≡ 1 (mod φ(N))`，即 D 是 E 对 φ(N) 的模逆元。若"加密解密不可逆"，根本不是 RSA。
  - 签名/验签是同一对模幂的镜像：签名 `s = m^D`，验签 `m ?= s^E`，凸显 RSA 的数学对称性。
- **必须有模逆元 D = E⁻¹ mod φ(N)**。这是私钥的核心：
  - 若缺少这一步（直接拿 E 当 D，或随便取个数），加解密不成立。
  - 求 D 必须先保证 `gcd(E, φ(N)) = 1`（E 与 φ(N) 互素），否则模逆元不存在；常取 E=65537（或教学用 17）正是为此。
- **公钥 (N, E) 公开、私钥 (N, D) 保密，二者分离**。若"加解密用同一个值"或"公私钥相同"，是对称密码，不是 RSA。
- **必须处理明文空间**：消息 m 必须 `0 ≤ m < N`，否则模运算会丢失信息、无法还原。生产中 m 通常是对消息做哈希后的摘要（签名）或经 OAEP 填充（加密）。
- **必须说明确定性加密的缺陷 + 填充必要性**：
  - 裸 RSA 是确定性加密：相同明文 → 相同密文，可被字典攻击；还可被选择密文攻击（CCA）利用。
  - 生产实现必须用 **OAEP**（加密）/ **PSS**（签名）做随机化填充。若"教学省略"必须显式声明，不能默认裸 RSA 安全。
- **N 必须足够大**（≥2048 位）。若 N 仅 50 位（如教学用 N=3233）且未声明仅供演示，几毫秒即可分解，安全性归零。
- **不能抗量子**：必须如实承认 Shor 算法可在量子计算机上多项式时间分解 N，RSA 不具备后量子安全性。
