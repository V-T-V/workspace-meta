# XOR 密码 · 设计笔记

## 历史

- XOR 运算本身不是某个人的发明，是布尔代数的基础操作
- 作为密码使用可以追溯到 20 世纪初的电报加密
- Vernam 1917 年的"Vernam 机器"用 XOR 加密电传打字机信号，被视作**一次性密码本（OTP）的硬件实现**
- 二战起 XOR 成为众多机械/电子密码机的底层操作；现代则是所有流密码的数学内核

## 核心算法

```
加密：C[i] = P[i] XOR K[i mod len(K)]
解密：P[i] = C[i] XOR K[i mod len(K)]   （与加密完全相同的运算）
        ↑ 依赖 XOR 自反性：(a XOR b) XOR b = a
```

密钥短于明文时循环复用（本包实现的就是这种"循环 XOR"）。

## 最小可识别特征

1. **对称**：加密与解密是同一个操作（同一段代码）
2. **逐字节/逐位**：每一位独立运算，无扩散（改 1 位明文只改 1 位密文）
3. **无混淆也无扩散**：密钥与密文的关系是最朴素的代数关系

## 判定红线

- 如果密钥与明文等长、纯随机、绝不复用 → 是**一次性密码本（OTP）**，信息论安全，**不是**普通 XOR 密码
- 如果密钥流由"种子密钥 + 伪随机生成器"产生（非密钥直接循环） → 是**现代流密码**（RC4 / ChaCha20 / Salsa20），**不是**本包的循环 XOR
- 如果不是逐位 XOR 而是"分块替换 + 多轮混淆" → 是**分组密码**（AES / DES），**不是**流密码

## 为什么单独 XOR 不安全

- **密钥空间 = 密钥长度**：短密钥（如 `key`）只有 2^24 种可能，暴力秒破
- **已知明文攻击**：攻击者只要拿到一组 (明文, 密文)，立刻算出密钥：
  `P XOR C = K`。一旦密钥在其他地方复用，整段密文全部泄露
- **无扩散**：明文与密文的差异是位级的、可见的，统计结构直接暴露
- **本包演示的"循环复用"正是 RC4/ChaCha20 极力避免的反面教材**——
  现代流密码绝不直接循环密钥，而是用密钥扩展出伪随机密钥流

## 与现代流密码的关系

| 维度 | 本包循环 XOR | 一次性密码本 OTP | 现代流密码（ChaCha20） |
|------|--------------|------------------|------------------------|
| 密钥 | 短密钥循环复用 | 与明文等长纯随机 | 短种子 → PRNG 扩展成密钥流 |
| 安全性 | 几乎无 | 信息论安全 | 计算安全 |
| 实用性 | 仅教学 | 不实用（密钥分发难） | 实用、广泛部署 |

三者本质都是 `密文 = 明文 XOR 密钥流`，区别只在"密钥流怎么来"。

## 本包实现要点

- 逐字节 XOR，密钥循环复用（`key[i % len(key)]`）
- 空 key 等价于不加密：原样返回拷贝（不报错，便于教学演示）
- 解密 == 加密（XOR 自反），独立提供 Decrypt 仅为接口对称
- 依赖 `core.HexEncode` 把不可见的密文字节打印成十六进制
