# MD5 · 设计笔记

## 历史

- 由 MIT 的 **Ronald Rivest**（RSA 的 R）在 **1991 年** 设计，1992 年作为 RFC 1321 发布
- 设计目的是替代此前已被发现弱点的 MD4
- 1990 年代到 2000 年代初是事实标准：文件校验、密码存储、Unix 系统指纹、TLS 证书签名……
- **2004 年王小云团队**在 CRYPTO 大会发表实用碰撞攻击，能在普通 PC 上秒级构造 MD5 碰撞
- 此后 MD5 全面退出安全敏感场景，仅保留在非安全用途（文件校验和、ETag 等）

## 核心算法（高层）

```
输入任意长度 M：
  1. 填充到 512 位（64 字节）的整数倍（追加 1 位 + 填 0 + 64 位长度）
  2. 切成 512 位的块，逐块送入压缩函数
  3. 压缩函数做 64 轮运算（4 轮 ×16 步），状态为 128 位
  4. 最终的 128 位工作变量即摘要
```

本包**不手写压缩函数**，直接用 Go 标准库 `crypto/md5`。

## 最小可识别特征

1. **无密钥**：任何人都能算同一个摘要
2. **不可逆（单向）**：从摘要无法（在计算上）反推输入
3. **定长输出**：恒为 16 字节（128 位）——这是和 SHA-256（32 字节）最直观的区别
4. **雪崩效应**：输入改 1 位，输出大约一半比特翻转

## 判定红线

- 如果**有密钥**且**可解密还原原文** → 是**加密**，**不是**哈希
- 如果输出 **32 字节（256 位）** → 是 SHA-256，**不是** MD5（MD5 恒为 16 字节）
- 如果输出 **20 字节（160 位）** → 是 SHA-1（也已破解，不应用于新系统）
- 如果**声称"安全"** → **不可能是 MD5**：MD5 已被碰撞攻击，不能用于任何安全场景

## 为什么 MD5 已不安全

- **碰撞攻击实用化**：王小云 2004 年的攻击能在秒级找到任意两个同摘要的不同输入
  - 后续研究（Stevens 等）进一步把"有目标的碰撞"做到可以伪造 X.509 证书
- **直接后果**：
  - 攻击者可以构造两份内容不同但 MD5 相同的文件，骗过基于 MD5 的完整性校验
  - 2008 年 CA 证书被伪造的事件（伪造 CA 签发的"合法"证书）就是 MD5 碰撞的实战
- **因此 MD5 不可用于**：数字签名、TLS 证书、密码存储、HMAC 之外的任何安全场景

## 与 SHA-256 对比

| 维度 | MD5 | SHA-256 |
|------|-----|---------|
| 设计者 | Rivest（1991） | NSA（2001） |
| 输出 | 16 字节（128 位） | 32 字节（256 位） |
| 轮数 | 64 | 64 |
| 碰撞复杂度 | **已被攻破**（秒级） | 2^128（生日攻击下界，无实用攻击） |
| 现状 | 仅非安全用途 | 推荐首选 |

## 什么场景还能用 MD5

MD5 仍是合法的**非安全哈希函数**，在以下场景完全可用：
- **文件校验和**：检测传输/存储是否损坏（非恶意篡改），如 ETag、备份比对
- **缓存键 / 去重指纹**：只在乎"不同输入大概率不同指纹"，不在乎抗碰撞
- **非安全 ETag**：HTTP 缓存校验
- **Git 早期对象**（Git 实际用 SHA-1，但同思路：内部去重，不抗恶意攻击）

**红线**：只要攻击者有动机构造碰撞，就不能用 MD5。

## 应用（已废弃 vs 仍可用）

- ❌ 数字签名：已被全面弃用
- ❌ TLS 证书：已禁用
- ❌ 密码存储：早就不该用（应改用 bcrypt/Argon2/scrypt）
- ✅ 文件校验和、缓存指纹、非安全去重

## 本包实现要点

- 直接调用标准库 `crypto/md5.Sum`，不手写压缩函数
- 用 `core.HexEncode` 把 16 字节摘要转成 32 字符 hex 小写串
- demo 与 sha256 包对照，强调"16 字节 vs 32 字节"和"已破解 vs 安全"
