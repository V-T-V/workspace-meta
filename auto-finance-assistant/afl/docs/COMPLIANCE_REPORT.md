## 一、法规框架

### 1.1 适用法律法规

本系统作为**本地化部署**的 AI 客服，处理金融业务咨询，涉及以下法规：

| 法规 | 核心要求 | 与本系统的关系 |
|------|----------|---------------|
| **《个人信息保护法》(PIPL)** | 个人信息处理需告知同意、最小必要、可删除 | 用户在对话中可能输入手机号/身份证等 PII |
| **《数据安全法》** | 数据分类分级、风险监测、应急响应 | 金融业务数据属"重要数据" |
| **《生成式人工智能服务管理暂行办法》** | 内容安全、日志留存≥60天、违法违规内容处置 | 系统输出由 LLM 生成，需内容审核 |
| **《个人信息安全规范》GB/T 35273** | 收集、存储、使用、删除、共享全生命周期管理 | 系统存储对话历史含个人信息 |
| **《网络安全法》** | 网络安全等级保护、日志留存≥6个月 | 服务端日志和审计记录 |

### 1.2 本地化部署的合规优势

相比云端 API（如调用 OpenAI/百度文心）：

- ✅ **数据不出域**：对话数据全程不离开部署机器，无需跨境数据传输评估
- ✅ **模型可控**：模型权重在本地，不存在第三方数据泄露风险
- ✅ **网络隔离友好**：可部署在内网/物理隔离环境，满足金融行业"数据不出机房"要求
- ✅ **无需算法备案**：使用开源模型自部署，不涉及"具有舆论属性或社会动员能力的算法"备案（如仅供内部客服使用）

### 1.3 本地化仍需满足的合规要求

即使本地化部署，以下义务**不可豁免**：

1. **个人信息保护**：对话中的 PII 仍需脱敏存储/传输，用户有权要求删除
2. **内容安全**：LLM 输出可能产生违法/不当内容，需事前拦截 + 事后审计
3. **日志留存**：操作日志、对话日志需留存法定期限（管理办法≥60天，网安法≥6个月）
4. **访问控制**：管理后台需认证，防止未授权访问用户数据
5. **数据保留期限**：不得无限期保存用户数据，需有 TTL 或定期清理机制

## 三、整改建议（按优先级）

### P0 — 必须立即修复

1. **启用审计日志写入**：所有写操作（FAQ/文档/备份/合规拒答）必须记录到 `audit_logs`
2. **数据保留 TTL**：会话/消息/反馈默认保留 90 天，超期自动清理
3. **安全响应头**：添加 X-Content-Type-Options / X-Frame-Options / CSP
4. **Rate Limit**：聊天接口 10/min，管理接口 30/min

### P1 — 一周内

5. **内容安全增强**：输出检查增加歧视/暴力/违法建议检测
6. **模型调用审计**：每次 LLM 调用记录 action=model_invoke
7. **日志保留期调整**：`retain_days` 从 30 调整到 60（满足管理办法最低要求）
8. **定时清理调度**：每日执行 `PurgeExpiredData`

### P2 — 月度规划

9. **传输加密**：支持 HTTPS（自签名证书 / 内网 CA）
10. **认证增强**：密码哈希存储、session token、登录审计
11. **用户删除权 API**：`DELETE /api/conversations/{id}` 按需删除
12. **CORS 配置化**：`allowed_origins` 白名单
